> 项目：AI Panel Studio（AI 圆桌讨论演播厅）
> 范围：从需求拆解到端到端验收的完整开发过程
> 关键词：Vibe Coding · 规范驱动 · 测试兜底 · 多房间异步隔离 · 输出脱敏

## 模块一 · 开发流程与工具链协同

本项目以 **Trae 作为 Vibe Coding 的主体 IDE**。与「把一句话丢给 AI 等结果」不同，整个开发过程把 Trae 的 Agent 模式当作一名**具备上下文感知与终端执行能力的结对工程师**：它读取仓库中的 PRD、schema、既有代码与测试失败输出，据此调整下一步动作；我在每个关键节点定义边界、审阅产出并用终端命令做客观验收。终端自愈能力（读取 pytest 报错 → 定位文件 → 修复 → 重跑）让「红转绿」的循环可以高频发生，而不需要人工搬运堆栈信息。

复杂需求被拆解为五个可验收的阶段，每阶段都有明确产物与门禁：

| 阶段 | 目标 | 关键产物 | 门禁 |
| --- | --- | --- | --- |
| **SDD** 规范驱动 | 先冻结领域模型与接口契约 | PRD.md、schema.sql、ARCHITECTURE.md、API.md | 建表脚本可在 SQLite 实际执行；SSE 六类事件载荷字段固定 |
| **TDD** 测试驱动 | 先写断言，再写实现 | test_scheduler.py、test_insight.py、scheduler.py、insight_extractor.py | 7 条用例由全红转全绿 |
| **DDD** 领域组件驱动 | 按领域边界拆分前端 | 演播厅三栏、PersonaCard、LiveTranscript、InsightBoard | `npm run build` 通过；根节点无全局滚动条 |
| **Integration** 集成 | 打通 SSE 全链路与并发隔离 | llm_service、room_manager、routes、前端流式消费 | 单房间事件计数正确；双房间 `wrong_room = 0` |
| **E2E** 质量闭环 | 系统级验收与交付样例 | sanitizer.py、seed_data.py、test_e2e.py | 8 条测试全绿；5 场样例一键灌库 |

这种「阶段化 + 门禁化」的拆解带来两个直接收益：其一，AI 每次只面对一个可验证的子问题，输出更聚焦，减少跨层幻觉；其二，任何阶段的回归都能被上一阶段的契约立刻捕获，例如调度器改动若破坏 1–2 句约束，TDD 用例会先于 UI 报错。

工具链协同的核心不是「让 AI 多写代码」，而是**让 AI 的每一次输出都落在一个可自动判定真伪的闭环里**：规范定义什么算对，测试定义如何证明，终端负责执行证明。

## 模块二 · 与 AI 协同中的三个典型技术冲突与解决路径

### 案例 1：调度器退化为机械循环发言

**现象**：AI 初版实现看似「不重复」，实则接近随机轮转——在特定随机种子下会形成隐性周期（如 1→2→3→4→1），且无法证明立场冲突真的影响了选择。

**冲突本质**：自然语言描述的「非机械轮流」无法直接转化为可测试的行为，AI 容易用「随机打乱」冒充「动态加权」。

**解决路径**：把模糊要求改写成可证伪的断言。新增 `test_scheduler_rejects_mechanical_rotation`，逐一否定周期 1–10 的循环序列，统计 20 次调度的重复块与单人占比；再配合「同一专家连续发言禁止」与「主持人连续交锋后强制接管」两条用例。测试先行后，AI 被倒逼引入**「立场冲突加权 + 冷静期衰减」的加权状态机**：上一轮立场对立的专家获得高额反驳欲望加权，刚发言者进入强制冷却，主持人计数器达到阈值后权重置为无穷大。红灯逐一转绿，调度行为从此可解释、可回归。

### 案例 2：SSE 长连接的事件混杂与协程挂死

**现象**：初版在客户端刷新或断线后，后端事件生成器未被及时释放，协程长期挂死；多房间并发时事件还会串房；缺少心跳与强制刷新时，代理缓冲导致文字明显卡顿。

**冲突本质**：流式推送天然是「长生命周期 + 多订阅者 + 易断线」的并发场景，单条生成器很难同时承担隔离、保活与清理三种职责。

**解决路径**：引导 AI 把隔离维度显式化为 `room_id`：每个房间持有独立的 `RoomRuntime`、独立 `asyncio.Queue` 集合与独立序号，广播只扇出到本房间订阅者；SSE 生成器增加 `: ping` 心跳、`request.is_disconnected()` 检测与 `finally` 释放订阅；响应头统一关闭缓冲（`X-Accel-Buffering: no`）。最终用脚本实测单房间事件计数，并同时运行两个房间验证 `wrong_room = 0`，把「隔离」从口头承诺变成可量化证据。

### 案例 3：总结阶段泄漏 Markdown JSON 语法块

**现象**：大模型在总结时经常返回 ` ```json {"summary": "...", "consensus": [...]} ``` ` 这类带围栏与键名的文本。若直接透传，前端终结卡片会显示花括号与引号，排版彻底破坏；类似地，发言中夹带 `[举手]`、`系统通知:` 等旁白，也会污染现场速记。

**冲突本质**：模型输出是「概率性自然语言」，而前端渲染契约要求「确定性纯文本」，两者之间缺少一层强制的类型转换边界。

**解决路径**：引导 AI 在服务端出站前建立 **Sanitizer 清洗管道**，而不是在前端做兜底字符串截断。管道分三层：先用正则提取 `"summary"` 字段，再用 `json.loads` 尝试解析对象，最后按「代码围栏 → 系统旁白 → 舞台提示 → JSON 键标签 → Markdown 标记 → 空白压缩」的顺序逐层剥离；任何一步得到空结果都降级到演播厅兜底陈词。同时用 `StreamingSanitizer` 在流式增量阶段抑制未闭合的 `[` 片段，用 `sanitize_focus` 把公开摘要硬截断到 15 字、整行丢弃 CoT 标记。E2E 测试直接对 SSE 帧断言「无 `{`、`}`、反引号、`"summary"`、无乱码、无控制字符」，使清洗成为可回归的质量门禁。

## 模块三 · 对「工程化 AI 开发」的理解

三个案例指向同一个结论：**AI 编程不是玩具式一键生成，而是规范驱动开发（Spec-Driven）与测试兜底（Test-Driven）的工程化结合。人类负责定义物理边界与验收断言，AI 负责高速实现，方能产出高可靠的工业级软件。**

具体而言，人类不可让渡的职责有三项。第一是**定义边界**：单次发言必须 1–2 句、每个房间只能有一位主持人、结束房间必须有总结——这些规则要被写进 PRD、下沉为数据库 CHECK 约束、再转化为测试断言，而不是停留在口头描述。第二是**定义验收**：什么叫「非机械轮流」、什么叫「没有 JSON 泄露」，必须变成可执行的判别条件；无法被测试的形容词，最终都会变成无法维护的代码。第三是**审阅与取舍**：AI 可以快速给出多个实现，但架构分层的取舍、并发模型的隔离维度、哪些复杂度现在不该引入，仍需要人类判断。

当这三项职责被认真履行时，AI 的速度才真正转化为工程产能：规范让它在正确的轨道上生成，测试让每一次生成都可被证伪，终端让证伪结果即时可见。本项目的 8 条测试、5 场样例与一条可复现的启动命令，正是这种协作方式的交付物——它不仅「能跑」，而且**每一次修改都能被证明仍然能跑**。这也是我认为 Vibe Coding 走向工业级的关键：把感觉变成规范，把规范变成断言，把断言变成持续执行的工程纪律。
